# 불변식 — 지켜야 하는 것과 그 이유

> CLAUDE.md §4 의 절대 규칙을 **근거·실패모드·검사 위치**와 함께 푼 것이다. 해당 절만 읽는다.

## 1. 모듈 경계

| 규칙 | 왜 | 어기면 | 검사 |
| --- | --- | --- | --- |
| Core(`ableops-kafka`, 과거 `kafka-control-portal`)의 어떤 패키지도 import 하지 않는다 | `internal/` 은 외부 모듈에서 컴파일조차 안 된다. Core 도메인 타입은 수시로 바뀐다 | 외부 확장이 빌드 실패 · Core 리팩터링 = 모든 확장의 Breaking Change | `TestSDKDoesNotImportCore` · `TestSDKDoesNotImportInternal` |
| go.mod require 는 `gopkg.in/yaml.v3` 하나 | SDK 가 가벼운 것이 분리의 목적. 늘어난 의존은 소비자 모듈 그래프에 실려 나간다 | 컴파일·테스트는 통과하므로 아무도 못 알아챈다 | `TestSDKModuleRequiresStayMinimal` · `TestSDKHasNoUnexpectedDependency` · `verify.sh` 의존성 최소성 |
| 핸들러는 `net/http` 만(chi 금지) | 라우터를 소비자에게 강요하지 않는다 | — | `TestSDKDoesNotImportChi` |
| SDK 는 "최소 Core 버전"을 상수로 들지 않는다 | 의존 화살표가 뒤집힌다(Core 릴리스마다 SDK 를 고쳐야 함) | SDK 버전이 API 변경 기준으로 움직이지 않게 된다 | 코드리뷰(Core 쪽 `sdkcompat.go` 가 선언) |
| `testdata/sdk-consumer` 픽스처에 Core 를 import 하지 않는다 | 그러면 외부 빌드 검증이 무의미해진다 | — | 코드리뷰 |

## 2. v1 호환성 (Breaking Change 금지)

v1 이 사는 동안 **금지**:

- 공개 심볼·필드·메서드 **제거** · 개명 · 시그니처 변경
- **인터페이스에 메서드 추가** — 외부 구현체가 전부 깨진다. 새 인터페이스를 만들고 `HostContext` 에 `RequireX` 헬퍼로 노출한다
- capability · 오류 코드 · 헤더 · 환경변수의 **문자열 값** 변경
- 기존 capability 의 **의미 확대**(read 에 쓰기를 얹는 등)
- Manifest 에 **필수** 필드 추가(선택 필드는 가능)

**허용**: 타입·필드·상수·함수 **추가**, 선택 Manifest 필드 추가, 문서·버그 수정.

골든 규칙(`extension/v1/testdata/api-v1.golden`):

| 골든 diff | 의미 | SemVer |
| --- | --- | --- |
| 변화 없음 | 버그 수정·문서 | Patch |
| 줄이 **추가만** 됨(단 `imethod` 줄 추가는 예외 — 그것은 Breaking) | 하위 호환 확장 | Minor |
| 줄이 **사라짐** 또는 바뀜 | Breaking Change | v1 에서 금지 → `extension/v2` 신설 |

갱신은 `UPDATE_SDK_API_GOLDEN=1 go test ./extension/v1 -run TestPublicAPISnapshot` 후 **diff 를 눈으로 확인**한다.
골든 편집은 `settings.json` 이 ask 로 막아 두었다 — 손으로 고치지 않고 항상 테스트로 생성한다.

네 개의 버전축은 서로 독립이다: Extension Version(Manifest) · API Version(`ableops.io/extension/v1`) ·
Protocol Version(`1`) · SDK Version(`SDKVersion`, 모듈 태그). 자세한 것은 [릴리스.md](릴리스.md).

## 3. `extserver` 프로세스 프로토콜 v1

- **환경변수 이름은 계약이다**: `ABLEOPS_EXT_ID` · `ABLEOPS_EXT_VERSION` · `ABLEOPS_EXT_CALL_TOKEN` · `ABLEOPS_HOST_URL` ·
  `ABLEOPS_HOST_TOKEN` · `ABLEOPS_EXT_CAPABILITIES` · `ABLEOPS_EXT_CONFIG` (+ 프로토콜 버전). 새 변수는 **선택**으로만 추가한다.
- **핸드셰이크는 stdout 한 줄**: `ABLEOPS_EXT_READY {"addr":"127.0.0.1:…","version":…}`. 구형식 파서 호환을 깨지 않는다(`TestReadyMessage_구버전호환`).
- 호환되지 않으면 기동하지 않고 `ABLEOPS_EXT_INCOMPATIBLE {...}` 을 낸다 — Core 는 이 줄을 보면 **재시작하지 않고 격리**한다. 이 줄을 없애면 무한 재시작이 된다.
- **포트는 Extension 이 고르고 주소는 항상 루프백**이다. Core 가 미리 고르면 확보와 사용 사이에 race 가 있다.
- **토큰·평문 시크릿은 로그·오류·핸드셰이크 어디에도 출력하지 않는다**(`Environment.String` 이 가린다). 토큰 비교는 상수 시간.
- 핸들러·Health 의 **패닉은 흡수**해 500 으로 바꾼다 — 확장 하나가 프로세스를 죽이지 않는다.
- 예약 서브경로(`health` · `install-events` · `enable` · `disable` · `update` · `rollback` · `assets`)와 `/api/extensions/<id>` 접두를 벗어난 라우트는 기동 시 거부한다.
- 미선언 capability 의 HostContext 필드는 **진짜 nil**(typed-nil 아님)이다. `RequireX` 는 `CAPABILITY_UNAVAILABLE` 을 돌려준다.

## 4. `testkit`

- **관대하면 안 된다.** 옵션으로 주지 않은 capability 는 nil 이어야 실제 Core 와 같다. testkit 이 채워 주면 "테스트는 통과하는데 설치하면 안 되는" 확장이 생긴다.
- `testing` 패키지에도 의존하지 않는다 — 통합 테스트·로컬 도구에서도 써야 한다. 반환은 `[]string`(위반 목록).
- 표준 라이브러리 + SDK 만 import 한다.
- **새 capability/서비스를 추가하면 fake(`fakes.go`)와 `WithX` 옵션을 함께 추가한다.** 빠지면 확장 개발자가 그 capability 를 테스트할 수 없다.

## 5. `frontend/v1` (TS 계약)

- 타입·상수만 둔다. 로더 구현은 Core(`web/src/extensions/remoteEntry.ts`)에 있다.
- Core 의 `web/src/extensions/contract/` 는 이 디렉터리의 **바이트 동일 사본**이어야 한다(주석 한 줄도 다르면 Core 의 `TestFrontendContractMatchesSDK` 실패).
  → 여기서 고친 뒤 **SDK 릴리스 → Core 에 복사** 순서다. Core 쪽을 먼저 고치지 않는다.
- 브리지 형태를 바꾸면 `FRONTEND_BRIDGE_VERSION` 을 올리고 `MIN_FRONTEND_BRIDGE_VERSION`·`supportsBridgeVersion` 으로 하위 호환을 판정한다.
- 이 저장소에는 TS 도구가 없다. 변경 후 Core 저장소에서 `npm run check:bridge` 로 검사한다(미실행이면 "미검증"으로 보고).

## 6. 문서·주석 관례

- 한국어. 패키지 주석은 "무엇/왜/철칙/파일 지도" 순서(`doc.go` 참조). 주의는 `⚠` 로 시작한다.
- 테스트 이름은 `TestX_한글설명`(언더스코어 뒤 한글). 게이트 테스트 이름은 CI 가 **이름으로** 확인하므로 개명하면 `verify.sh` 의 `GATES` 목록도 함께 고친다.
- 오류 메시지는 한국어이며 시크릿을 담지 않는다.
- 분리 이전 경로(`sdk/extension/v1`, `kafka-control-portal/…`)를 새 주석에 쓰지 않는다. Core 저장소 문서를 가리킬 때는 "Core 저장소의 …" 라고 명시한다.

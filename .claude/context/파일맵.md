# 파일맵 — 어디를 고치는가

> 패키지 3개 + 예제 1개 + 프론트 계약 1개, 전부 `github.com/heartblast/ableops-sdk` **한 모듈**이다.
> 각 패키지 `doc.go` 에 파일 단위 지도가 있다 — 여기는 "하려는 일 → 파일" **역인덱스**다.

## 1. 저장소 골격

| 경로 | 무엇 | 공개 API(골든 대상)? |
| --- | --- | --- |
| `extension/v1/` | Extension API v1 계약 — 타입·인터페이스·Manifest·capability·권한·버전 | ✅ |
| `extension/v1/extserver/` | 외부 프로세스 Extension 런타임(`Run`) · 프로세스 프로토콜 v1 wire | ✅ |
| `extension/v1/testkit/` | 확장 개발자용 fake Host · 계약 점검 헬퍼(`CheckExtension` 등) | ✅ |
| `extension/v1/testdata/api-v1.golden` | 위 3패키지의 공개 심볼 스냅샷 | 계약 그 자체 |
| `extension/v1/testdata/sdk-consumer/` | **별도 go.mod** 를 가진 외부 소비자 픽스처. `TestExternalConsumerCompiles` 가 임시 디렉터리로 복사해 빌드 | — |

| `.gitattributes` | `* text=auto eol=lf` — 골든 바이트 비교를 CRLF 에서 지킨다 | — |

## 4. 문서·예제만 고칠 때

- README 코드 블록은 `examples/hello-extension` 과 어긋나기 쉽다. **예제를 먼저 고치고 README 를 맞춘다.**
  README 에 새 코드 블록을 넣으면 `go doc` 이나 임시 모듈로 실제 컴파일되는지 확인한다.
- `verify.sh fast` 로 충분하다. 단 CHANGELOG 의 `## vX.Y.Z` 제목을 건드렸으면 `full`(버전 게이트).
- `frontend/v1` 은 Go 검증 대상이 아니다 → [불변식.md](불변식.md) §5.

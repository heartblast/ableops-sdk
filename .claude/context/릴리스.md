# 릴리스 — SDK 버전 올리기와 Core 동기화

> SDK 버전은 **SDK 공개 API 변경 기준으로만** 올린다. Core 릴리스 때문에 여기 항목이 늘지 않는다.

## 1. 버전 결정

골든(`extension/v1/testdata/api-v1.golden`) diff 로 판정한다.

| 골든 diff | SemVer | 예 |
| --- | --- | --- |
| 없음 | **Patch** | 버그 수정 · 문서 · testkit 내부 개선 |
| 줄 추가만(`imethod` 추가 제외) | **Minor** | 새 capability · 새 선택 필드 · 새 헬퍼 |
| 줄 삭제·변경 · `imethod` 추가 | **Major** | v1 에서는 금지. `extension/v2` 를 새로 만든다 |

Protocol Version(`protocol.go`)은 wire(환경변수·헤더·핸드셰이크·Host API 경로)가 바뀔 때만 올린다. SDK Minor 와 무관하다.

## 2. 절차 (셋을 한 커밋에서 맞춘다)

1. `extension/v1/compat.go` 의 `const SDKVersion = "X.Y.Z"` 를 올린다.
2. `CHANGELOG.md` 맨 위에 `## vX.Y.Z — YYYY-MM-DD` 절을 만든다(`## v` 로 시작하는 첫 제목이 게이트 대상).
   변경 · 유지(Breaking 아님) · 호환성 표 순서로 쓴다. `## 미출시` 절이 있었다면 그 내용을 여기로 옮긴다.
3. `frontend/v1` 을 고쳤으면 `FRONTEND_BRIDGE_VERSION` 정책을 확인하고 CHANGELOG 에 "Core 재복사 필요"를 적는다.
4. 커밋한다(clean 트리여야 release 검증이 통과한다).
5. `bash scripts/verify.sh release` — 전부 통과.
6. `git tag vX.Y.Z && git push origin main vX.Y.Z` (둘 다 settings 에서 ask — 사용자 확인 후).
7. `go list -m github.com/heartblast/ableops-sdk@vX.Y.Z` 로 프록시에서 보이는지 확인(네트워크 필요, 실패해도 태그는 유효).

## 3. 릴리스 뒤 Core 저장소(`ableops-kafka`)에서 할 일

이 저장소에서는 할 수 없다. 사용자에게 목록으로 넘긴다.

- `go get github.com/heartblast/ableops-sdk@vX.Y.Z && go mod tidy`
- `internal/extensionhost/sdkcompat.go` 의 지원 범위 갱신(Minor 이상)
- `frontend/v1/*.ts` 를 `web/src/extensions/contract/` 에 **바이트 동일**하게 복사(변경했을 때만) → `TestFrontendContractMatchesSDK` · `npm run check:bridge`
- Core 의 `sdk/` 스테이징과 이 저장소를 동기화(추출 절차는 Core 저장소 `docs/reference_docs/extension-sdk/12-SDK저장소분리.md`)
- 참조 확장(`ableops-flink`)의 require 갱신. 확장의 `go` 디렉티브가 SDK 의 `go` 값(현재 1.27.0) 이상인지 확인한다

## 4. 하지 않는 것

- 태그를 옮기거나 지우지 않는다(모듈 프록시에 캐시된다). 잘못 나갔으면 다음 Patch 를 낸다.
- `retract` 는 명확한 결함(빌드 불가·보안)일 때만 go.mod 에 추가한다 — go.mod 편집은 ask 다.
- v1 골든에서 줄을 지우는 릴리스는 없다.
